# Match Point Padel Points v2

A clean React/Vite frontend focused on the exact product logic requested.

## Formats

### League
- Padel only.
- Fixtures are generated by the league.
- No manual **Add Match** button.
- Shows the fixed league schedule.

### Friendly Group
- Players can add 2v2 padel matches manually.
- Friendly Group now includes a points system.
- Default: **Win = 3 points, Loss = 0 points**.
- Standings sort by points first.
- Match history and recent form are shown.
- Scoring can be changed from **Points settings** using **Save points**. Values must be non-negative whole numbers.
- Sidebar **Matches** and **Settings** open the group's match history and points settings.
- **Add player** adds a named player to the group, match selectors, standings, and search. Player names must be 2–60 characters and cannot duplicate an existing name.
- **Delete all matches** asks for confirmation before clearing Friendly Group results and resetting standings. Players, scoring settings, and League fixtures are kept.

## Frontend only

There is no backend. Players, friendly matches, and scoring settings are stored in browser `localStorage`.
Invalid saved entries are ignored while valid matches are retained. If saving is unavailable, the app shows a warning and remains usable for the current session.

## Checks

```bash
npm test
npm run build
```

The tests cover standings, invalid results, storage recovery, save failures, and local match dates. Use Node.js 22 or newer.

With the dev server running, `npm run test:browser` checks desktop and mobile flows using a separate temporary browser profile. It detects Chrome or Edge on Windows; set `BROWSER_PATH` for another Chromium installation and `APP_URL` if using a different server address. This check requires Node.js 22 or newer.


## Added functionality

The existing design was kept intact. Functional additions only:

- Friendly Group points remain enabled.
- League player entry.
- Random round-robin generation: every league player faces every other player once.
- Extra manual League matches.
- League result entry and automatic standings.
- Existing notification UI was intentionally kept.
- No `.env` file is required.
- Current persistence uses localStorage.
- `src/services/backendAdapter.js` is the future backend integration boundary.
